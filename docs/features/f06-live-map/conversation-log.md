# F06 — Live Map · Implementation Log

Implementation sub-agent, 2026-10-13, branch `feature/f06-live-map` (base: F00 + F01 + F04 + F05 on `main`).

1. **Read inputs**: F06 spec + intent, architecture §4, decision log (D-005, D-020, D-031…D-040), the live-tracking engine/fleet-state/status-deriver/store/diagnostics code, F04/F05 test reports, `mock-server/generator/catalogue.ts` (40 centres) and `vehicle-sim.ts` (loops 1.5–~18 km around a centre).
2. **Dependencies**: `maplibre-gl` 6.14 and `supercluster` 9.1. supercluster 9 ships its own types, so `@types/supercluster` was added and removed again.
3. **Config**: `map-config.ts` (India bounds, radius 60, max zoom 14, unclustered zoom 15, rebuild 2000 ms, cap 5000, fit padding 48 / max zoom 14, locate zoom 16 / 1 s, debounce 100 ms). `india-cities.ts`: the 40 generator centres (name + state), box = centre ± 22 km, sorted A–Z; a node test checks it against `CENTRES`.
4. **Worker** (`map-index.ts`): supercluster over every vehicle with a valid position, `map`/`reduce` keep a flat per-status object (flat so supercluster's shallow clone can't share arrays). Zoom ≥ 15 → live bbox scan into a reusable `Int32Array`; over the cap → clustering at lower zooms until it fits. Points below zoom 15 are looked up live by `vehicleId`. `bounds()`, `expansionZoom()` (null on stale ids), `frameBuffers()`. `position.ts` holds the shared validity rule.
5. **Engine**: `setViewport` / `getClusterExpansionZoom` / `getBounds`; `dataVersion = state.version + statusEpoch` (sweep changes); throttled rebuilds with a catch-up timer; `push.mapFrame` only when data or the index changed; `stats.clusterBuildMs`; a `transfer` dep (Comlink's `transfer` in the worker entry, identity in Node) transfers every typed array of a frame, both in replies and pushes.
6. **Store**: `mapFrame` + `notice` in the state; `setViewport`, `locateVehicle`, `fitToVehicles`, `jumpToCity`, `zoomToCluster`, `notify/dismissNotice`; `onMapCommand` channel (fit / fly / ease); auto-fit once when snapshot complete **and** a viewport exists; newest frame version wins; `selectedPosition()` helper. Still no React imports (the existing guard test now also scans `map-index.ts` and `position.ts`).
7. **Unit tests**: T1–T3 + engine integration in `map-index.test.ts`, T5 in `map-index.perf.test.ts` (1 lakh: rebuild 67–91 ms, frames ≤ 4.6 ms), T4 in the store test.
   - Problem: `StatusTracker` needs the charging PID columns; the test fleet used `pids: []`. Fix: `statusLafPids(statusRulesConfig)`.
   - Problem: with fake timers `performance.now()` is frozen, so `clusterBuildMs` was 0 in the engine test. Fix: assert the plumbing (equals `map.buildMs`); T5 measures real time.
   - Problem: the first T5 viewports never hit the cap (2500 vehicles per city). Fix: add a z15 viewport over four western cities (capped → clusters).
8. **UI**: `live-map.tsx` (WebGL check, lazy `map-controller`), `map-controller.ts` (style, controls with expanded OSM attribution, SDF arrow/dot icons generated at runtime, status colours via `getComputedStyle`, GeoJSON symbol layer, highlight ring layer, DOM cluster markers reused by id, hover popup, click-select, 100 ms debounced `moveend` → `setViewport`, executes store commands), `cluster-marker.ts` (SVG donut string, short Indian counts), `map-toolbar.tsx` (fit button, searchable city popover), `debug-overlay.tsx` (moved F04/F05 diagnostics, collapsible, cluster rebuild + frame stats, "Locate vehicle ID"), `live-tracking-page.tsx` (sr-only h1, toast).
   - Problem: MapLibre 6 computes its worker URL from `import.meta.url`, which points into Vite's pre-bundle. Fix: `setWorkerUrl(maplibre-gl-worker.mjs?url)` (D-045).
